# M1 · 在本地目录发起只读文件任务

Windows 开发构建中，右侧 Agent 的「文件任务」可以用 DeepSeek Harness 回答关于所选文本的问题。任务在提交时就绑定来源目录：切到其他文件夹、网页或 SSH，不会把回答送进当前聊天。普通聊天、已有历史和原有的修改审阅功能仍使用原引擎。

本页记录 M1 只读问答。后续开发版另提供 [M2 单文件审阅写入](HARNESS_M2.md)、[M3 网页引用](HARNESS_M3.md)和 [M4 远程目录问答](HARNESS_M4.md)。当前索引为 `tasks-v4.json`；旧索引的迁移与回退见 M4 文档。

从 M5 RC4 起，预览另一目录的同名文件不会撤销原预览。已打开的预览只使用当时确认的快照；主动关闭、改变任务类型或停用引擎后要重新预览。关闭已经提交的窗口不会取消后台任务。

## 第一次试用

1. 启动桌面开发构建或 [M5 候选包](HARNESS_M5.md)，在「设置 → Agent 引擎」检查并启用 Harness。在右侧 Agent 的模型设置中明确选 **Anthropic Messages**。使用 DeepSeek 时填入 `https://api.deepseek.com/anthropic`、账号可用的模型名以及对应的 API Key。也可以使用本机测试服务 `http://127.0.0.1:端口/v1`。不支持的路由会提示原因，不会回退到其他服务。
2. 打开一个本地文件夹，在文件列表中选中 1–3 个普通的 UTF-8 `.md` 或 `.txt` 文件。若固定了 Agent 项目，请进入该项目目录再选文件。每个文件最大 32 KiB，合计最大 64 KiB；拒绝链接、网络盘、二进制内容和受保护的 `.dalizi` 路径。
3. 选择「文件任务 → 预览所选文件」，检查完整正文、服务地址和模型。输入问题（最多 4000 字）再点「将以上快照发送给模型」。预览不会请求模型，五分钟后需要重新预览。即使原文件内容发生变化，提交的也是预览中的文字。
4. 可以关闭面板、切换目录。回到原目录，在「文件任务 → 任务记录」展开回答；要寻找已移动或不再浏览的目录，可明确勾选「查看所有目录」。同一路径创建的新目录不会接管旧任务。这里的每个问题都是独立任务，不会携带上一轮问答。

一次只运行一个任务。重复提交同一份预览和同一个问题不会再次调用模型；RC6 起，沿用已经提交的预览编号换问题会被拒绝。若要追问，请重新预览后提交。切换双面板时，「文件任务」取左侧工作面板的选择；想问右侧文件，先点「设为工作目录」。

在任务记录中选择「停止任务」会终止本机运行时；已发送的请求能否取消计费取决于模型服务。应用意外退出后，下次打开任务列表时显示「结果待核对」，不会自动重发。已结束的任务可以移除；记录达到 64 条时须先移除旧记录。

## 数据与边界

RC3 起，文件任务遇到限流、服务故障或连接中断时，不会自动重发已选资料。历史里会显示对应的处理建议；不要把断线理解为服务端一定没有收到或计费。真实账户的一次性验收步骤见[联网测试说明](WINDOWS_GUEST_QA.md#另行验收真实模型)。

| 数据 | 去向 |
| --- | --- |
| 本次问题、选中文件名和预览正文 | 交给预览中显示的服务；不附加其他文件、目录记忆、历史对话、浏览器或 SSH 内容。 |
| 问题、文件名、来源目录及身份、模型、地址、状态和回答 | 保存在 `%LOCALAPPDATA%\com.dalizi.files\HarnessTasks\tasks-v4.json`，不写入用户项目。这是本机明文记录；回答可能引用原文。 |
| SDK 临时会话 | 每个任务在应用数据目录下使用独立临时目录；正常结束时回收，意外退出时在下次读取任务记录时尝试清理，移除记录也会重试。 |
| 模型密钥 | 使用当前会话的密钥或对应服务的 Windows 凭据；不写入任务索引，不作为命令行参数。 |

Rust 宿主负责读取、预览和路由；真实 dsh 在空工作目录运行，模型没有文件或命令工具。这个受限配置不是 Windows 系统沙箱。M1 最初只在开发版开放；M5 候选包已增加组件完整性校验，干净系统验收仍待完成。网页引用、SFTP 文件读取、Harness 修改审阅及多轮会话恢复不属于本轮实现。

## 如何复现

需要 Windows x64、WebView2、Rust 桌面工具链及本地开发运行时。将 Node 24.22.1 的 Windows x64 官方归档解压到 `%LOCALAPPDATA%\DaliziDev\node-v24.22.1-win-x64`；按 [M0 说明](HARNESS_M0.md)把 `@deepseek-ai/dsh@0.2.2-rc.3` 安装在同级的 `runtime-0.2.2-rc.3`。在呆梨项目根目录安装测试依赖后运行：

```powershell
npm ci
# 使用默认 Rust 工具链（MSVC 需要可用的 C++ 工具与 Windows SDK）
.\tools\verify_harness_desktop.ps1
# 本次实际使用的替代工具链：Rust GNU + 本机 DaliziDev\w64devkit
.\tools\verify_harness_desktop.ps1 -Toolchain stable-x86_64-pc-windows-gnu
```

两条验证命令任选一条。[验证脚本](../tools/verify_harness_desktop.ps1)在独立构建目录生成测试程序，使用单独的应用标识和 WebView2 数据，不覆盖日常使用的可执行文件。脚本启动真实桌面程序和固定版本的 dsh；只有模型由本机回环 HTTP 服务模拟，不使用付费密钥。普通开发构建仍可从项目根目录运行 `cargo build --locked --manifest-path src-tauri/Cargo.toml --bin dalizi-files`，然后从 `src-tauri\target\debug` 启动 `dalizi-files.exe`，保留旁边的 WebView2 DLL。

## 验收记录 · 2026-11-16

- 真实桌面测试在 A、B 创建同名文件；预览 A 后修改原文，提交后切 B，再打开未连接的 SSH 标签。实际模型请求只有预览时的 A 内容，工具清单为空；A 有回答，B 和 SSH 没有，磁盘内容未被 Agent 修改。
- 通过原生 IPC 验证错误来源目录和不支持的模型协议会被拒绝。重复提交只发一次；停止运行中的任务会保留已停止状态。
- 在另一个请求进行中强制关闭桌面进程，观察到模型连接关闭。重启后已完成的回答和已停止状态仍在，中断任务不重发，其临时目录已清理；移除记录后所属目录的列表为空。
- Rust 快照与协议测试覆盖目录替换、硬链接、大小限制、无效 UTF-8、提前断流和事件归属。另用 Edge 检查了既有工作台和标签页交互。本次未调用真实云端模型，也未连接实际 SSH 服务器；以上断言不作为生产安装包验收。
