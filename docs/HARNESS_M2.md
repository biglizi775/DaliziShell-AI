# M2 · 审阅并应用文件修改

开发版或 [M5 候选包](HARNESS_M5.md)启用 Harness 后，「文件任务」提供两种任务：默认的只读问答，以及对一个本地文本文档提出修改。两者都使用不带文件工具的 Harness 进程。写入和撤销由呆梨在 Windows 上执行。

## 使用

1. 按 [M1](HARNESS_M1.md) 配置模型。在本地文件列表选中一个普通的 UTF-8 Markdown 或 TXT 文件（不超过 32 KiB），将 Agent 权限设为「确认后执行」。
2. 打开「文件任务」，将类型改为「提出修改，审阅后写入」，预览原文、服务地址与模型，再发送修改要求。
3. 在该目录的任务记录中展开「待审阅，尚未写入」，点击「审阅差异」。核对**目标目录、文件名、原文和建议稿**后点击「确认写入此文件」。关闭差异窗口只返回任务；「放弃提案」使它永久失效。
4. 已写入的任务可选择「撤销此次写入」。确认前不会修改文件。若原文带 UTF-8 BOM 或使用统一的 CRLF/LF 换行，建议稿沿用原格式；撤销恢复备份中的原始字节。混合换行文档以审阅的建议稿为准。

切到 B、网页或 SSH 可以看历史，但只能在目标所属的本地目录审批。切换到只读或自动模式会撤销该目录的待审提案，并要求停止仍在生成的修改任务。切回「确认后执行」不会复活旧提案。预览可提交五分钟，生成的提案可审阅十分钟；退出程序后，未批准的提案失效。新引擎不支持自动写入。

本页的索引说明对应 M2。含[网页引用的 M3 开发版](HARNESS_M3.md)使用 v3 索引，并保留旧版本记录。

## 写入、撤销与意外退出

| 场景 | 结果 |
| --- | --- |
| 模型返回操作命令、其他文件名、附加字段、空文本或超限建议 | 任务失败，不创建备份，不修改目标。仅接受含 `target` 和 `replacement` 的 JSON 对象。 |
| 文件在预览后被人工编辑，或被另一个同名、同内容文件替换 | 在独占打开的文件句柄上核对物理身份和原始字节；不匹配则保留磁盘内容，需要重新生成。 |
| 重复批准、使用旧审批、切换目录或从其他任务借用审批 | 后端核对任务、目录、权限和一次性审阅凭证；不能再次产生文件效果。 |
| 确认写入 | 先持久记录「正在写入」，再将原文备份至项目的 `.dalizi/edits`，最后修改文件并记录结果。备份含文件身份、这次操作的编号和新版本摘要。 |
| 撤销 | 只恢复这个任务写入的版本；后来手工编辑、有更新的备份或文件身份变化时，保留当前文件。该项目原有的「撤销上次 Agent 修改」仍可使用。 |
| 正在等待模型或审阅时异常退出 | 不重发模型请求，不恢复旧审批；没有获得批准的提案不会写入。 |
| 已批准，写入或撤销期间进程中断 | 重启提示核对目标和备份，不自动再次写入。备份先于原位写入；这个流程不保证断电时目标文件仍完整。 |

应用数据 `HarnessTasks/tasks-v2.json` 记录任务状态。首次从 M1 升级时读取 `tasks-v1.json`，不就地覆盖它；回退到 M1 只能看到旧索引。新索引损坏时报错并保留原文件，不会悄悄回退到过期列表。手动移除已迁移的任务也会移除旧索引内同一条记录。移除记录不等于撤销文件修改，也不删除项目的最近一次恢复备份。审批令牌和待审原文、建议稿只保存在内存中。

## 开发与复现

- [宿主任务](../src-tauri/src/harness_tasks.rs)管理索引持久化和重启；[审阅服务](../src-tauri/src/harness_review.rs)解析提案并核对审批；[共用文档写入](../src-tauri/src/ai_document_edit.rs)在同一文件句柄上比较、备份、写入和撤销。
- [桌面联调](../tools/verify_harness_desktop.ps1)编译独立测试程序，同时运行 M1 和 [M2 场景](../tools/harness_m2_checks.cjs)。它启动真实 Tauri、WebView2 和 dsh，使用本机模型夹具；覆盖差异审阅、切目录、拒绝、单次批准、人工修改、重启后撤销、权限撤销和重启后旧审批失效。没有访问云端模型。另有 Rust 测试覆盖同名同内容替换、索引迁移、损坏索引和备份归属。
- [Windows CI](../.github/workflows/ci.yml)将 Harness 检查与一般前端和桌面构建分开。Node 固定为 24.22.1；开发运行时依赖由[专用 npm 锁文件](../resources/harness/dev-runtime/package-lock.json)固定。全新开发目录可复制同目录的 `package.json` 与锁文件，以 `npm ci --ignore-scripts --no-audit --no-fund` 安装。不要在已有个人运行时目录执行覆盖安装。这份锁文件用于复现开发测试，不是发行版签名或安装包。

在呆梨仓库根目录运行：

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml --bin dalizi-files
.\tools\verify_harness_desktop.ps1 -Toolchain stable-x86_64-pc-windows-msvc
```
