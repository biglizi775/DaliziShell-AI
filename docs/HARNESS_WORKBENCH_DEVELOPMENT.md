# 呆梨文件与 DeepSeek Harness 集成开发文档

**状态：开发设计稿 v1.0，2026-11-16。** 面向产品、桌面端、运行时和测试开发者。目标平台为 Windows 10 / 11 x64。下文是总体设计，当前可用能力以各阶段的实现与验收记录为准。

开发版已接入 [M0 协议联调](HARNESS_M0.md)、[M1 桌面只读任务](HARNESS_M1.md)、[M2 审阅写入与撤销](HARNESS_M2.md)、[M3 网页引用](HARNESS_M3.md)和 [M4 远程目录只读任务](HARNESS_M4.md)。网页引用归用户明确选择的本地项目；SFTP 问答归已核验的远端账户、主机及目录。普通聊天与历史归档仍用原引擎。[M5 本地候选包与验收记录](HARNESS_M5.md)已包含可独立停用的运行时、完整性检查、诊断导出和回退说明。已在 Windows 11 开发机上用[两台独立的 Linux OpenSSH 服务器](verification/harness-openssh-windows11.json)验证同名远程路径的隔离，回答由回环模型提供。干净 Windows 10/11 x64 上的首次启动、整机断网、公开版二进制回退和真实云端模型鉴权仍待验收。

保留 Dalizi Files 的 Tauri 桌面、文件管理、WebView2 和 SSH/SFTP；把 DeepSeek Harness 作为可替换的 Agent 执行引擎。产品的核心约定是：**标签决定用户正在看什么，任务记录决定 Agent 可以操作什么。切标签可以改变下一次提问的对象，不能改变已经发出的任务。**

第一次交付只解决一个日常问题：在目录 A 选中文件，请 Agent 解释；等待时转去看目录 B、网页或服务器；回来后，回答仍在 A，且整个任务只收到当时选中的内容。第一版不需要给模型开放终端、整盘文件或浏览器控制权。

## 2. 用户如何识别目标

输入框上方永久显示“**执行目标 · 权限 · 引用资料**”。例如：`本地：订单项目（D:\订单）｜只读｜需求.md 快照`。路径可展开复制，远端显示账户、主机、端口及远程路径。每条任务卡也保存提交时的目标；后台结果出现时只在原项目显示未读标记，不切换窗口或覆盖当前草稿。

| 用户动作 | 界面行为 | 后台行为 |
| --- | --- | --- |
| 在“跟随标签”模式从 A 切到本地 B | 输入框切到 B 的草稿与对话；A 的任务继续显示在任务列表。双面板须显示取自哪一侧。 | 重新计算下一次提交的目标；A 的绑定保持不变。 |
| 固定 A 后打开网页或 SSH | 始终显示“固定：本地 A”。不自动附上网页、远端文件、终端输出或 B 的选择。 | 仅 A 有执行权；引用其他来源须单独选择并预览。 |
| 未固定项目，在网页或兼容 SSH 终端提问 | 明示“尚未选择任务目标”，提供“引用到项目…”或“选择本地项目”；支持远程只读后，内置 SSH 才增加“在此远程目录提问”。 | 缺少目标时拒绝提交；用户仍可显式选择收件箱作为普通本地项目。 |
| A 运行中关闭标签、修改权限或切换模型 | 关闭标签只隐藏视图，可从任务列表找回。更换模型或放宽权限只影响新任务；撤销授权立即阻止旧任务继续执行新动作。 | 不通过标签序号寻找任务。撤销时使旧授权失效，终止受影响的运行；已发生的操作按实记录。 |

“引用网页”只表示把一份带来源的内容交给模型。哪怕网页写着“去服务器修改配置”，引用也不会创建 SSH 连接、授予写权限或改变执行目标。

## 4. 工作区、任务和数据归属

以下是呆梨内部设计，不是 Harness SDK 的字段。**一个任务只有一个执行目标，可以携带多份引用；引用不能反向授予对其来源的访问权。**

| 实体 | 最少字段 | 归属和约束 |
| --- | --- | --- |
| `Workspace` | `workspaceId, kind, displayName, locator` | Rust 分配稳定 ID。本地定位记录规范根路径与可用的卷/目录身份；远端定位记录已核验主机指纹、账户、端口、远程系统和根目录。网页型记录标识页面会话，首版只能用作来源。 |
| `ViewBinding` | `windowId, tabId, paneId, mode, workspaceId?` | 只描述视图当前指向哪里。两个同名目录、两台主机上的同名路径、两个窗口的同序号标签均不能据此合并。 |
| `ReferenceSnapshot` | `refId, sourceKind, sourceLabel, capturedAt, contentHash, boundedContent` | 提交前可查看、移除。文件来自当前目标内经过验证的选中项；网页保存用户选择的标题、地址及文本。内容按采集时冻结。 |
| `ConversationBinding` | `conversationId, workspaceId, engine, sessionId, runtimeHomeId, profileRevision` | 锁定所属工作区与引擎；仅在来源身份、版本和权限策略允许时恢复。界面会话 ID 不等于上游会话 ID。 |
| `TaskBinding` | `taskId, conversationId, workspaceId, targetSnapshot, grantId, refIds, engineRevision, status` | 提交时持久化不可变目标。另存运行代次、模型路由、消息收据和最终状态；后台事件不能修改绑定。 |
| `Grant` | `grantId, taskId, resourceScope, allowedOps, revision, expiresAt` | 后端签发，可撤销；远端还绑定本次已认证连接代次。审批和运行句柄不随项目复制或重启恢复。 |

目录注册、文件打开和写入提交均在后端校验；不用路径字符串前缀或小写化结果证明归属。初版只承诺本地普通盘符目录；UNC、设备路径、无法验证的重解析点等应明确显示不支持。目录移动或原路径换成另一目录时暂停恢复，要求重新绑定。远端路径按远端系统解释；禁止用 Windows 路径处理函数拼接服务器路径。

**存储与迁移。** 旧目录的 [聊天归档](../src-tauri/src/agent_conversations.rs) `.dalizi/chat-history.json` 与 `.dalizi/agent-memory.json` 保持现有语义和读写方式。新引擎把机器相关的工作区映射、任务索引、展示摘要保存在当前 Windows 用户的应用数据目录，运行时日志写入应用私有的 `DSH_HOME`；项目目录不保存令牌、进程号或可用授权。应用索引采用版本化结构、事务提交；先登记任务，再启动进程。SDK 日志负责原始会话事实，呆梨索引负责 UI 列表与最终投递记录，不直接编辑上游日志。

升级时先允许只读打开、导出旧对话；需要续聊时由用户选取旧对话摘要或目录记忆，预览后作为新会话的资料。不要把旧对话 ID 当作 SDK session，不要把历史工具调用重新执行。项目迁移到其他机器时，目录记忆和旧归档仍可读取；缺少本机 SDK 日志时只显示可用档案，不声称恢复现场。提供按工作区删除本机任务、快照和 SDK 历史的入口，明确列出删除范围；便携设置默认不导出这些内容。

按工作区清理已在[独立开发预览](PREVIEW_workspace-history.md)中实现。确认范围含已结束任务、归属此目录的预览和旧索引记录，以及相应的运行时临时目录。确认时重新核对目录身份、清单与索引。[Windows 11 验证记录](verification/workspace-history-preview-windows11.json)列出同名目录、不同 SSH 主机、网页快照、文件锁与重启用例，和 RC6 的正式签收分开。

## 5. Tauri 与 SDK 接口

建议的 Tauri 命令及返回如下。外部网页不具备调用这些命令的能力；Rust 校验调用方的 WebView 身份，并检查窗口是否拥有相关会话。只检查窗口标签不足以区分同窗中的外部子 WebView。

| 拟建命令 | 输入 → 输出 | 服务端职责 |
| --- | --- | --- |
| `agent_bind_target` | 本地选择或已认证连接的资源标识 → 目标摘要与 `bindingId` | 解析身份、显示名、可用操作；不能用前端提供的任意路径切换既有任务。 |
| `agent_capture_reference` | `bindingId`、选中项/网页选区 → `refId` 与预览 | 检查大小、类型、来源和身份；网页导航后旧选区作废。 |
| `agent_submit_task` | `bindingId, conversationId?, refIds, prompt, mode, clientRequestId` → `taskId` | 核验所有引用与目标；相同提交键返回原任务，拒绝同键不同内容。提交时固定引擎与模型。 |
| `agent_task_get` / `agent_task_list` | 任务或工作区 ID → 快照与事件游标 | 面板重开、事件漏收后从本地记录补齐；不重复向模型发请求。 |
| `agent_stop_task` | `taskId` → 停止中或既有终态 | 停止新动作、废弃待审批请求；收到进程退出或执行者回执后再更新最终状态。 |
| `agent_review_action`（第二阶段） | `taskId, proposalId, expectedHash, decision` → 已应用/拒绝/冲突 | 审阅对象和内容必须与提案相同。调用两次只能有一次文件效果；文件变化要求重新生成差异。 |

宿主向 UI 发布拟建事件 `agent-task-event`，携带 `taskId, workspaceId, conversationId, seq, kind, summary`。序号由 Rust 在事务内按任务递增；UI 按序号去重，发现缺口时重新查询。用户打开 B 时收到 A 的事件，只更新 A 的任务记录。模型回复、网页文字或文件正文均按不受信任的内容渲染。

### 5.1 一次只读任务的协议顺序

1. Rust 在本地生成任务 ID，保存绑定，按固定版本启动 `dsh --profile sdk` 并应用呆梨维护的受限补丁。子进程的启动目录为受信安装目录，不能从用户项目加载启动脚本或配置。标准输出只用于每行一条的 JSON-RPC；标准错误另行读取，限制长度并脱敏。
2. 调用 `initialize({cwd, provider, model, ...})`；检查返回的 `serverInfo.name`、版本兼容清单及实际部署配置。握手按**进程**设置工作目录和模型路由。MVP 一次只允许一个任务运行，独占一个进程；新的提交可排队。恢复同一会话使用相同受控 home，不在不同目标间共享活进程。
3. 新会话直接发送 `session/prompt({sessionId, contentBlocks})`；已有会话先执行 `session/resume({sessionId})`，成功后再发送。只把本次同意提供的快照及提示作为输入；有历史的会话本身可以包含过去已提交的内容。首版使用 `session/prompt`，不将自由文本送进能执行原生命令的 `session/query`。
4. `session/prompt` 返回 `messageId` 表示**已入队**。发送前即订阅并缓冲通知；仿照固定版本 SDK 客户端，以本会话收据对应的 inbox 事件确认输入进入本轮，结合 `session.event` 的已提交输出、终止原因和 `session.status` 判断结果。`session/wait` 用于等待已存在的会话收束，单独的空闲状态或成功 RPC 都不能判作已回答。未匹配当前进程代次和 session 的事件不投递。
5. 先持久化结果，再通知面板。成功或失败均发送 `shutdown` 并等候退出；关闭管道、回收句柄。恢复不会重新广播完整历史，历史展示从本机档案读取。恢复失败时保持原档案，只提供显式新建会话。

协议示例（独立请求样例；其中模型和路径须替换为实际已核验值）：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"cwd":"D:\\订单","provider":"deepseek-official","model":"<已配置的模型>"}}
```

```json
{"jsonrpc":"2.0","id":2,"method":"session/prompt","params":{"sessionId":"<新会话ID>","contentBlocks":[{"type":"text","text":"请总结我选中的需求文档。以下是用户已预览的文件快照：……"}]}}
```

### 5.2 停止与异常恢复

任务状态为 `queued → starting → running → succeeded / failed`；运行中可进入 `awaiting_review`、`stopping`。排队时取消可直接记为 `cancelled`。运行中停止时先撤销工具授权，再请求专属子进程关闭，超时后结束受管进程树；只有确认没有未决副作用，才能记为 `cancelled`。当前协议没有通用的 `session/cancel`。本地进程退出也不能保证已发出的模型请求没有计费。

无法确认一个已发出请求或写操作的结果时，记为 `outcome_unknown`（结果待核对）。程序启动时检查遗留非终态任务，显示最后确认的步骤；不重发提示、审批、写入或远端操作。消息解析失败、未知 session、管道断开和回复晚到均有可识别错误码；用户重试创建关联的新任务。协议超时和进程退出超时分别计时，不用自动重试掩盖不确定结果。

## 6. 能力、权限与资料边界

**MVP 不开放任何模型工具。** Rust 核实当前工作区和所选文件，读取有界文本，显示预览，用户发送后交给模型分析。它能回答“帮我看这份文件”，不能回答“自行扫描整个仓库”。运行时仍需读取自身程序、写入会话库、访问已配置模型服务；“只读”约束的是对用户资源的操作，不影响应用保存聊天。

不要原样交付 `sdk`：默认含读、写、编辑等工具。也不要把 `sdk-minimal` 当作只读版本：它默认提供持久 shell。以固定版本的命名 profile 加受控配置启动，关闭文件/终端工具、PTC 执行器、插件安装、MCP、子 Agent、定时任务、外部技能和工作区配置自动发现等入口。检查模型实际收到的提示、资料和工具列表，不能仅凭配置文件名称判定只读。若不能裁到可验证的程度，停在隔离测试目录，改用只组合所需插件的 profile 后再接入用户目录。

| 权限模式 | 首次提供 | 可执行范围 |
| --- | --- | --- |
| 只读 | M1 | 仅分析用户选定并预览的快照。M3/M4 增加的来源分别授权；读取资料不代表允许修改来源。 |
| 确认后执行 | M2 | 只对本地项目的 Markdown/TXT 修改生成提案。用户查看目标、原文和差异后，Rust 核对授权、文件身份与内容哈希，再调用现有审阅写入逻辑。 |
| 自动执行（当前目录） | M2 后独立评审 | 旧引擎保留既有策略；新引擎在操作白名单、撤销和冲突测试齐备前显示“暂不支持”。将来逐项开放，不默认授予删除、覆盖、shell 或远端写入。 |

**写操作归属。** 首个可写版本让模型只返回结构化文档提案，Rust 解析、展示、审批并落盘。仅接受目标内已选定的普通文本文件；复用现有 32 KiB 修改上限、编码/换行处理、并发校验和备份机制。文件变化时拒绝旧提案。SDK 的 `approval/request` 提供 session、工具名称以及可选的 callId、原因等信息，不足以核实具体路径和差异。以后若启用原生工具，必须能关联到完整动作描述；没有对应提案就拒绝。

**资料与凭据。** 建议 M1 只收 UTF-8 的 TXT/Markdown，每任务最多 3 份，每份 32 KiB、合计 64 KiB。超限、二进制、不可读或文件已更换时明确提示，不静默截断。禁止把 `.dalizi`、凭据文件或网页表单作为自动上下文。预览列出将发送的来源、范围和模型服务，区分新快照、已有对话历史和用户选取的旧记忆。诊断默认只记 ID、阶段、耗时和脱敏错误，不记正文、Cookie、私钥、口令或 API Key。

模型密钥仍由宿主按服务地址从 Windows 凭据管理器取用，不通过命令行、项目文件或前端事件传递。子进程只获本次模型适配器需要的环境；不继承 SSH 凭据、其他提供方密钥或完整父进程环境。旧版的 Chat Completions、Responses 和 Anthropic Messages 配置不可假定与 Harness 等价。各路由逐一验证请求地址、认证和错误行为；尚不兼容时允许用户显式选择旧引擎，不自动换模型、地址或密钥。

## 7. 浏览器和 SSH 接入

**网页引用（M3）。** 用户选中文字，点“引用到项目”，选择对话并核对预览。宿主校验来源 WebView 和导航代次；只传用户确认的文本与来源地址，不读取 Cookie、密码、隐藏表单或整页历史。地址默认去掉查询参数与片段。采集前页面跳转或关闭则要求重选；采集后保存快照，不随网页更新。自动操作浏览器留给后续独立设计，应使用可见、可停止、按会话隔离的浏览器环境，不默认复用日常登录态。

**远程只读（M4）。** 从“内置 SSH → 在 SFTP 面板选中文件 → Rust 读取快照 → 在此远程目录提问”开始。在本机受控的空目录启动 Harness；远程路径是有来源的元数据，不可作为 Windows 的 `cwd`。复用已有主机指纹核验与认证；读取时重新确认连接代次、账户、根目录和文件身份。不能证明链接目标仍在授权范围内就拒绝。兼容 OpenSSH 终端没有同样的结构化文件句柄，不从屏幕猜目录或注入命令。

断线后未完成的采集作废；若已完成采集并提交，模型可继续解释该快照，回答显示“来自断线前的快照”。重连后重新绑定授权。若后续需要模型按需取文件，在呆梨侧增加列目录、读取指定普通文件等工具，凭短期任务令牌调用 Rust 的 SFTP 服务；这需要新建受限的双向适配，不是 SDK stdio 已有的远程接口。SSH 命令执行、远端写入和跨主机搬运另行验收。

## 8. 本地开发与 Windows 分发

两个项目保留独立依赖和构建目录。开发机需要 Git、Rust MSVC、VS C++ 工具链、Windows SDK 与 WebView2。两端一起开发时，采用 Harness 基线要求的 Node.js ≥ 24.9.0，以及其包清单固定的 pnpm 11.28.5；呆梨的测试依赖仍按 npm 锁文件安装。以下命令分别在对应项目根目录运行。

```powershell
# 呆梨：现有桌面程序与基线测试
npm ci
npm test
Push-Location src-tauri
cargo run --locked --bin dalizi-files
Pop-Location
```

```powershell
# Harness：构建固定检出，检查命名 profile 的启动入口
pnpm install --frozen-lockfile
pnpm run build:artifacts
pnpm run build:check
pnpm dsh --profile sdk --help
```

最后一条只检查 CLI 入口，不能证明集成或权限生效。M0 先用无需真实密钥的假服务测试传输，再换真实 dsh 和模拟模型，跑完握手与一轮对话。M1 用显式配置的真实模型和人工样本做端到端验证。开发启动器与发行启动器分开，不把开发机绝对路径、源码、全局 pnpm 或系统已安装 Node 当作用户机器的前提。

**分发设计：** Windows x64 运行时作为独立组件，包含固定 Node、dsh 入口、必需包与原生依赖、受限配置、许可证及版本/校验清单。Rust 按安装清单定位，不从当前目录或任意 PATH 启动同名命令。隐藏控制台窗口，用 Windows Job Object 管理进程树；收起到托盘仍属运行，真正退出才回收全部子进程。组件启动失败只禁用新引擎，文件管理、浏览器和手动 SSH 保持可用。

在无 Node/pnpm 的干净 Windows 10、11 x64 上分别验收：首次启动、无密钥使用文件管理、中文和空格路径、便携位置不可写、缺失组件、网络不可用、退出无孤儿进程。记录包体增量、冷启动耗时、首个回复耗时、峰值内存和退出后进程数，再决定组件随主包分发或按需安装。更新时并排安装新组件；运行中的任务继续使用原版本直至结束。

| M2 本地审阅写入 | 独立提交提案解析、差异 UI、单次审批及文件状态复核；接入已有写入和恢复。 | 仅修改被授权的文件；拒绝、重复审批、文件变化和中断均有可见结果。 |

首个迭代先交 M0 的真实协议样本和能力清单，再交能脱离 UI 运行的客户端；随后用两个临时目录实现 M1 的目标绑定和事件路由，最后接入现有 Agent 面板。这样可以分别定位“协议不通”“配置无法限制能力”“结果送错对话”。M2 至 M4 共享 M1 的任务绑定，可独立上线；不要求用户为了引用网页先启用写入。

## 10. 验收矩阵

[普通 Agent 切换模型实测](verification/model-switch-windows11.json)覆盖 A 的自动摘要正在等待时，在 B 更换服务地址和模型并发送独立提问。四次回环请求核对了原轮次的模型和凭据、B 的独立回答、A 的计划确认、下一轮使用新模型以及主动停止。已保存的聊天仍可用原有归档格式读取。

[A02 固定项目子目录实测](verification/pinned-selection-windows11.json)覆盖普通 Agent 的「项目工具」。在固定项目的子目录选中文件后，只有显式点击「本次引用」，下一条请求才附上该选中项。换文件、切走标签和发送后的下一轮分别复核；同一选区的目录刷新、项目根目录选中项和右键文档编辑另有正向检查。此项在 RC7 之后的开发预览中交付。

[M5 RC4](verification/harness-m5-rc4-windows11.json) 增补 A01–A03、A09、A10 的预览交错场景：先在 A 核对快照，B 的同名文件完成预览，仍能按原编号提交 A；关闭本地预览不撤销其他网页或远程预览。切换权限只撤销对应目录的修改预览，停用引擎才会撤销全部未提交预览。

[RC5 的原项目未读标记](verification/harness-m5-rc5-windows11.json)将后台结果留在任务所有者的界面。打开列表不算已读；查看展开的结果后，只确认所见任务的那一版结果。A、B 草稿不受影响，SSH 按远端身份而非路径字符串区分。

[RC6 的 A03 原生用例](../tools/harness_m1_smoke.cjs)覆盖两个标签打开同一目录、连续提交、关闭原标签、交换双面板及恢复标签。相同问题重取同一条任务；同一预览编号换问题须明确拒绝。终态和重启后使用同一规则，重取回执不会重新调用模型。[RC6 验证记录](verification/harness-m5-rc6-windows11.json)包含开发机上的桌面实测、九阶段离线演练、11 项聊天回退检查及尚未签收的发布条件。

[M5 RC7 验证记录](verification/harness-m5-rc7-windows11.json)绑定了 history-scope 预览的生产 EXE、组件和编译用源码包。离线验收新增一条用户操作：在 B 的「查看所有目录」看到属于 A 的折叠行，再切回 B。点击后不应留下 A 的可操作行；B 显示空列表，A 仍有一个未读回答。Windows 11 开发机以独立应用标识实际跑完九个阶段和跨版本聊天回退。干净 Windows 10、Windows 11 和真实云鉴权三个报告仍待收集。

[A08 的 RC4 往返演练](verification/harness-m5-rc4-chat-rollback.json)覆盖旧版编辑新版聊天并返回的情形。记录将两款隔离 EXE 的 11 项行为检查与两个原始发行 ZIP/EXE 的只读摘要核验分开；没有在开发账户启动公开版或用新编译的 CI 构建代签本地包。

2026-11-16，M5 RC2 增补了 A08 的 Windows 11 实测：从旧标签构建的桌面保存聊天，当前桌面在移动后的项目读取并保存，旧桌面回读并续写，最后返回当前桌面。旧正文、目录记忆和便携偏好可读；早期内联步骤可显式整理。包哈希、两款测试程序的身份和其余发布门槛见 [RC2 验收记录](verification/harness-m5-rc2-windows11.json)。

A08 / A11 的[离线客机验收](WINDOWS_GUEST_QA.md)只依赖 Windows PowerShell 5.1 和 WebView2。同一套用例可以使用独立测试标识演练，也可以在干净客机上直接使用两份原始 ZIP。只有后者的报告可以签收对应的 Windows 版本。

[真实模型验收工具](WINDOWS_CLOUD_QA.md)与离线演练独立：操作者在发行程序中提交一次合成材料，重启后展开原回答。验收工具核对官方端点、A/B 任务归属与读态变化；[工具本机演练记录](verification/harness-m5-rc6-cloud-tool.json)记载的是回环回答被云端检查拒绝，没有真实鉴权结论。[发布核对命令](RELEASING.md#可重复打包与校验)按同一候选的 ZIP 和 EXE 摘要核对三个报告。

[M5 RC3](verification/harness-m5-rc3-windows11.json) 修复了旧快照配置继承运行时自动重试的问题。用更新后的桌面、r2 组件和回环服务注入 401、402、429、503，以及接收 POST 后断开连接：五种场景分别只收到一次所选快照；任务失败并留在发起目录，重启后归属不变。诊断只显示固定类别，不包含服务返回的自由文本。真实云端鉴权另行签收。

Rust 测试验证目标和执行权限；协议夹具注入乱序、重复与管道中断；现有 Node/UI 工具验证面板和路由；原生 Windows 测试负责真实进程、WebView2、SFTP 和安装包。使用临时目录及人工制作的文件，不以真实项目数据作为测试材料。

| 编号 | 操作或故障 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | A、B 各有同名 `需求.md`，内容分别为不同标记。在 A 提交，模拟模型暂停，切 B、再切 SSH，随后放行回答。 | 请求只有 A 的标记；A 记录一份结果，B/SSH 没有新消息；B 草稿未变，两份文件均未修改。 |
| A02 | 固定 A，在 B 选择文件；或未绑定时从网页/SSH 发送。 | 前者不夹带 B 的选择；后者要求显式选择，不使用收件箱兜底。 |
| A03 | 同目标打开两个标签，切换双面板；双击提交，关闭标签后重开。 | 提交键去重；按目标与会话找回原任务，不创建第二次模型调用。 |
| A04 | 只读任务收到要求写文件或执行命令的文本；提供超限文本、目录别名及工作区外文件。 | 模型工具清单为空；宿主拒绝不合规快照。核对文件内容和实际模型请求，不能只看模型回答。 |
| A05 | 注入握手错误、收据前事件、异会话事件、晚到回复和重复通知。 | 不把收据当回答，不向其他任务投递；重复事件不重复显示；错误可诊断。 |
| A06 | 在排队、推理中、等待复核三个时点点“停止”，随后退出或模拟崩溃。 | 重启显示最后确认状态，旧审批失效；未确认动作不重放；正常退出后受管子进程为零。 |
| A07 | 修改建议生成后用户另存新内容再批准；或连续批准同一建议两次。 | 前者提示冲突，不覆盖用户内容；后者至多写入一次；备份恢复保留原换行与编码。 |
| A08 | 从旧工作树副本升级、移动项目、切回旧引擎；模拟 SDK 日志缺失或版本不兼容。 | 旧记忆和聊天仍可打开；不覆盖旧归档，不以同名新 session 冒充成功恢复。 |
| A09 | 网页 X 选中后、采集前跳到 Y；采集后跳页；尝试从外部网页调用受保护命令。 | 前者需重选；后者保持 X 的快照；外部网页不能操作宿主。 |
| A10 | 两台服务器各有同名路径；采集时断线、重连，或主机指纹改变。 | 无跨主机读取；新连接不可使用旧授权；指纹变化须重验；已提交的资料带时间与来源。 |
| A11 | 干净机缺少或损坏运行时；模型路由不匹配；升级后回退组件。 | 新引擎可诊断、可停用，不悄悄改用其他模型；原有文件、网页和手动 SSH 功能可用。 |

M1 合入前执行 `npm test`、`npm run check`、`npm run test:workbench` 和 `npm run test:tabs`；新增 A01–A06、A08 中对应本地只读的回归用例。M2 增补 A06 中的待审场景与 A07；M3 增补 A09；M4 增补 A10，并运行已有 `npm run test:ssh-files` 和 `npm run test:ssh`。M5 以 A11 及安装/回退实测记录为门槛。PR 注明哪些结果来自夹具，哪些来自真实二进制或真实模型。

## 11. 发布、故障诊断与回退

实验开关默认关闭，从“设置 → Agent 引擎”显式启用；不能在失败后把同一提示自动发给另一引擎。界面显示目标、引擎版本、失败阶段和下一步，例如“运行时缺失”“目录已移动，请重新绑定”“修改结果待核对”。诊断包包含版本清单、能力清单摘要、事件编号和耗时，导出前可预览。

升级上游时比对协议方法、事件类型、默认工具、会话格式和原生依赖，再重放 M0 样本与跨工作区用例。不让新版本原地升级唯一一份可恢复历史：先备份或使用隔离的版本化数据目录，通过验证后再切换索引。回退时停止领取新任务，结清或标记未决任务，恢复旧组件或旧引擎；不倒写上游持久化格式，不删除用户项目中的 `.dalizi`。

呆梨和当前 Harness 源码均附 MIT 许可证。分发时保留各自版权与许可文本，按实际打入的 Node、原生模块等组件更新第三方清单。产品沿用呆梨名称；关于页面可写明“Agent 引擎基于 DeepSeek Harness”，不暗示上游官方背书。
