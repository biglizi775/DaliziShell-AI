# Windows 10/11 离线验收包：M5 RC7

用于回答一个问题：一台没有开发工具的 Windows 电脑，在没有外网的情况下，能否打开候选版、使用随包组件，并在回到公开版编辑后保留聊天？这是测试包，日常使用只需 RC7 应用包。测试不需要账号密钥、Node、pnpm、Python、Rust 或 Visual Studio。

## 在一次性 Windows 测试机运行

1. 分别准备 Windows 10（1809 或更高）和 Windows 11 x64 的干净客户端。测试账户须是**不属于 Administrators 组的普通用户**。系统已安装 WebView2 Runtime，未运行过呆梨、没有开发工具；先创建可还原的快照。不要在日常账户运行 Guest 模式。
2. 校验外层验收 ZIP 的 SHA-256，与旁边的摘要文件或交付记录比对。将包完整解压到普通用户可读的目录。包内包含两个**原封不动的 ZIP**：公开版 0.5.1 与本地 RC7。不要手动展开或改名。将输出报告保存到可写的用户目录。
3. 断开**测试机**的所有网络适配器，保留系统回环；脚本不修改适配器。打开 64 位 **Windows PowerShell 5.1**，进入验收包目录，先做只读检查：

~~~powershell
.\verify_windows_guest.ps1 -Mode Inspect
~~~

看到 `archiveHashesMatched: true` 后，核对 `windowsFamily` 是预期系统、`standardUser` 和 `freshProductProfile` 为 `true`、`activeAdapterCount` 为 0、`developmentCommandsOnPath` 为空。工具检查只反映 PATH；使用未安装开发工具的快照仍是测试前提。系统已有组织策略限制脚本执行时，使用管理员认可的测试镜像或脚本签署流程。

4. 在同一快照上运行正式测试，每个系统用一个**不存在**的报告文件：

~~~powershell
$report = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'dalizi-guest-acceptance.json'
.\verify_windows_guest.ps1 -Mode Guest -ConfirmDisposableGuest -Report $report
~~~

桌面会自动打开、关闭数次。等待 PowerShell 正常返回；失败时保留报告中的最后阶段和控制台错误，然后还原快照再测。成功也要先将报告复制出测试机，再还原快照。程序的用户配置由快照清除；脚本只清理自己的临时安装目录、项目和 WebView 数据。

## 实际检查

| 阶段 | 通过的条件 |
| --- | --- |
| 首次启动 | 完整候选包解压至含中文及空格的目录；无需密钥即可浏览合成项目；识别正确组件，引擎默认关闭。 |
| 缺失、损坏 | 从本次安装移走组件，再单独放入一份截断的测试文件。两次均不能启用引擎、文件浏览仍可用；恢复原组件。 |
| 只读安装与本地问答 | 对本次安装禁止写入，并实测写入被拒绝。错误接口在预览前被拒；A 预览后，B 另行预览并关闭同名文件，再从 A 提交并切到 B。随原包的本机模型仅收到所选标记、工具列表为空。结果和未读数只归 A，读过的回答在重启后仍为已读；失败与中断结果保持未读。诊断预览不含文件名、密钥、地址或回答。结束后恢复测试安装目录的权限。 |
| 离线故障与退出 | 关掉本机模型后再提交应显示失败。另一次请求收到但尚未回答时正常关闭桌面；等待已识别的随包 Node 子进程退出。重启后 A 里分别保留成功、失败和中断记录，B 为空。 |
| 跨版本 | 公开版写入正文、目录记忆和便携偏好，复制项目并保留原件。在新版读旧记录、存带步骤的新聊天；回到公开版读两条正文并续写；再打开新版能看到旧版续写内容和原步骤。查看旧数据不能改变原归档。 |

报告含系统 build、WebView2 版本、两份 ZIP 和实际执行文件的 SHA-256、各阶段结果、耗时、工作集和退出后的子进程数。它不包含用户名、路径、聊天正文或密钥。签收时核对 `mode: Guest`、`publicExecutables: true`、`passed: true` 和对应系统；两个系统的记录相互独立。离线测试使用随包的本机协议夹具，不验证真实云端鉴权。

在 B 打开「文件任务 → 查看所有目录」，验收会核对 A 的折叠行标出了归属。切回当前目录后，同一次点击内必须清除 A 的任务与操作，随后显示 B 的空列表；A 的回答仍是未读。

从 RC6 起，工具还会同时提交两次同一份预览，检查两次回执是否指向同一任务。随后用原编号换问题，必须明确拒绝。最后一次重启后，即便引擎已经停用，也应能按原问题取回原回答，不能受理换过的问题。

## 另行验收真实模型

RC7 有独立的[云端验收工具使用说明](WINDOWS_CLOUD_QA.md)。工具为每轮生成 A、B 和未选文件的随机标记，两次启动同一份已核对的桌面并比对任务记录，输出独立 JSON。它不改变本次冻结的离线包。需要可复核的报告时，请按工具说明操作；下列三步也可用于手动试用。

离线测试结束后，使用另一个联网测试环境做一次真实问答。用自己的临时测试密钥，只在桌面的模型设置中输入；不要把密钥写进项目文件、聊天或验收报告。

1. 创建两个临时目录 A 和 B。在 A 的 `notes.md` 写入随机生成的短标记，在 B 的同名文件写入另一个标记。只在 A 勾选这个文件。
2. 在 RC7 启用随包组件，选择 **Anthropic Messages**、官方端点 `https://api.deepseek.com/anthropic` 和该账户可用的模型。打开文件任务，检查发送预览与目标；提问“只抄出所选文件里的标记”，提交一次后切到 B。
3. 回到 A，检查回答是否包含 A 的标记、没有 B 的标记；重启后看 A 的这条记录仍在，B 为空。只记录日期、候选包摘要、模型名称、通过或失败及类别。只有实际收到已鉴权的回答才算通过；无效密钥得到 401 不算通过。

## 开发者复验

在仓库中，`tools/package_windows_guest_qa.py --previous <公开版ZIP> --candidate <RC7 ZIP>` 用两份固定摘要的原始归档生成离线验收包。在解压出的验收包目录内，可在开发机用 `-Mode Rehearse` 并提供 `-RehearsalOld`、`-RehearsalNew`、`-Previous`、`-Candidate`、`-Report` 复跑相同场景。此模式只允许此次已留证、使用独立应用标识的两个测试 EXE，仍使用原包组件；报告明确记作演练，不能用于签收干净系统。
