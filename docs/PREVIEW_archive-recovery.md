# 开发预览：对话保存失败后怎么继续

如果工作目录无法写入，或另一窗口已经更新了同一段对话，应用会暂停自动保存。此时再次关闭所属标签、新建对话、切换 Agent 项目或在固定项目里恢复历史，会看到**哪段对话、哪个目录、为什么没保存**。即使当前看的是 B 标签，处理的仍是 A 的记录。

| 选择 | 结果 |
| --- | --- |
| 保留并返回（或 Esc） | 停止这次关闭或切换，原文仍在。如果已有保存错误，正在接收的回复或待确认计划也会先留在原处。 |
| 重试保存 | 目录恢复可写后，按原版本重试。若是版本冲突，不会覆盖另一窗口保存的内容。 |
| 另存为新对话 | 在原工作目录创建一条独立记录。成功后才切换记录编号；失败仍可返回原对话。 |
| 放弃本次未保存的修改 | 允许继续原操作，不删除或改写磁盘上的记录。做选择期间又收到新内容时，旧选择不会替新内容作决定。 |

手动保存还在写盘时关闭标签，会等它完成；需要结束正在接收的回复时，已收到的部分也会计入保存。正在执行的文件操作需待执行完毕后再关闭所属标签。手动关闭自动保存、也没有待完成或失败写入的临时对话，不会因关标签被强制写入磁盘。

此预览沿用[工作区草稿与计划保留](PREVIEW_workspace-retention.md)。它保护的是应用内关闭或替换对话；输入框草稿仍在内存中，退出整个应用或断电前请先手动保存想保留的文字。发行验收仍以[冻结的 M5 候选](HARNESS_M5.md)为准。
