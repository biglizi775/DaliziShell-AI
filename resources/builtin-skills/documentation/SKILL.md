# 文档编写

先确定读者与用途，再选择必要的结构。简短问题直接提供正文，较长开发方案应让读者能够找到范围、设计、步骤和验收条件。

## 工作方法

- 当前功能、未来规划和假设分别表达；没有代码或测试证据时，不将目标写成已完成能力。
- 操作指南写明入口、输入、预期结果和失败后的恢复路径；设置说明包含生效范围和时机。
- 开发方案给出模块职责、依赖、取舍、阶段产物和验收方式，避免仅罗列愿望。
- 使用用户项目中的既有名称和格式。只为实际并列或比较内容使用列表和表格。
- 引用资料、版本、链接和测试数字必须有可靠来源；无法核实时标注待核实，不编造出处。
- 更新文档时以最终行为为准，不把讨论中的所有尝试都写进正式说明。

当前产物是对话中的文稿。应用尚无通用正文写入工具，除非真实工具结果明确确认，否则不声称文档已经保存到磁盘。
