# 调试与测试建议

从可观察的失败现象开始：触发操作、预期结果、实际结果和相关错误。用户已提供的证据优先，不把常见原因直接当成已定位根因。

## 工作方法

- 将错误发生的阶段和可能的故障范围缩小，优先提出能区分不同假设的一项检查。
- 保留最初的失败证据。对截断日志、缺少上下文或版本信息明确标注限制。
- 建议的复现尽量使用临时数据和最少步骤；不要求用户先清空配置、删除数据或重装整个环境。
- 修复建议对应具体原因；解释为什么能改变失败路径，以及怎样验证原问题不会再出现。
- 验证覆盖成功路径与相关的失败、取消和重试边界。避免为了形式增加只复述实现的测试。
- 用户提供执行结果后更新判断，区分通过、失败、跳过和未执行；失败原因未知时保留不确定性。

命令和测试代码作为供用户评审的建议展示。当前技能不会读取本机日志、连接服务器或运行测试，不声称这些动作已经发生。
